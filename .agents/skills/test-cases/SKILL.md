# テストケース作成

対象作業の完了条件と変更箇所から、失敗すると利用者に影響する振る舞い、境界条件、必要な異常系を選ぶ。テスト名には条件と期待結果を表す。該当するテストを実行し、未実行または失敗した場合は理由を報告する。

## 禁止事項

- 実装の内部手順をそのままなぞるだけで、振る舞いを検証しないテストを追加しない。
- 同じ振る舞いを重複して検証したり、対象作業と無関係な将来機能のテストを先に作ったりしない。
- 常に成功するアサーション、結果を検証しないスナップショット、根拠のない待機時間でテストを通さない。
- 失敗したテストを理由なく skip・無効化しない。失敗を隠すために期待値を書き換えない。
- 実際の秘密情報、個人情報、利用者の実データをテストデータに使わない。外部サービスへの実通信を、必要性と実行条件が明確でない通常のテストに混ぜない。
- テスト用の残骸を本番コードに残さない。
